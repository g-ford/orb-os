# Weather: three screens on the knob

Date: 2026-09-20. Status: design approved in conversation, spec awaiting review.

## Intent

Bring the Weather app back into the launch build and give it three screens, chosen by
turning the knob: **Now** (temperature and outlook icon), **Radar** (rain over the geo map),
**7-Day** (a week's forecast). Sources stay global (Open-Meteo, RainViewer), plain HTTP,
nothing routed through the zionbrock gateway. First tested from Brisbane, in the simulator;
hardware follows when the board arrives.

Not in scope: BOM as a source (its forecast API is HTTPS-only, which this board cannot
raise, and its radar is Australia-only); new theme keys; Orb Studio controls (see
"Theme surface").

## Findings that shaped this

- The weather app never used the gateway. `weather_client.cpp` calls Open-Meteo and
  `wx_radar_client.cpp` calls RainViewer, both direct. Only News, route lookup and the ticker
  use `INTEL_GATEWAY_HOST`.
- Weather is absent from the build because `APPS_LAUNCH_ONE` in `config.h` removes Weather,
  Surveillance and the Ticker together.
- The radar mode already draws RainViewer frames over the SD-card road and coast masks
  (`wx_map_prepare`, `wx_radar_client.cpp`), which is the geo reuse asked for. It is kept as is.
- The knob router delivers every turn to the app on screen and reserves the rock gesture for
  the app switcher (`input_router.cpp`). An app's turn handler is therefore free to step
  screens without capturing the knob.
- `src/app/weather/weather_view.cpp` is a dead earlier standalone app (its `init()` is never
  called, it hardcodes °F). It is left alone here.

## Design

### 1. Roster and defaults

- `config.h`: add `APPS_WEATHER 1`. `APPS_LAUNCH_ONE` continues to gate Surveillance and the
  Ticker only. Update the comments that say launch one is "exactly Clock, Flight tracker,
  News and Settings".
- Move the weather-only `#if !APPS_LAUNCH_ONE` sites to `#if APPS_WEATHER`: the forecast fetch
  and the radar fetch in `adsb_task`, the `app_shell::add` for Weather in `main.cpp` and
  `sim_main.cpp` (currently in one block with Surveillance, which is split), and `APP_WEATHER`
  in `app_shell::Slot`. The "theme asks for an app this build does not carry" notice drops
  Weather from its list.
- Default theme: `apps.weather` true and `names.weather` "Weather". The file
  `src/theme_assets/default/theme.yaml` is generated by `tools/gen_default_theme.py`, so the
  change is made at the source and the file regenerated. The generated file currently says
  `weather: false` although `Apps{}` defaults to true; finding out why is the first step, and
  `tests/test_default_theme.py` must pass afterwards.
- The portal theme already sets `weather: true` and names it "Weather Lab"; unchanged.
- Bump `FW_VERSION`. Do not run `tools/publish-firmware.sh` or the wrangler deploy:
  CLAUDE.md rule 1 requires a hardware boot first.

### 2. Knob

- Weather registers a turn handler. A detent steps Now -> Radar -> 7-Day and wraps in both
  directions. Entering the app always lands on Now.
- Push stays unassigned (the shell shows the standard knob hint).
- The old push handler `weather_press_cycle` and `ui_set_weather_forecast` /
  `ui_weather_is_forecast` are replaced by `ui_weather_step(int delta)` and
  `ui_weather_screen()`.
- Radar frames still start downloading on entering the app, so the radar is ready by the time
  the knob reaches it. The alternative (start on first selection of Radar) saves about 1.2 MB
  of PSRAM while on Now but makes the first turn wait 15-20 s. Revisit on hardware.

### 3. Screens

The weather tile in `ui.cpp` gains a three-way mode: `WEATHER_NOW`, `WEATHER_RADAR`,
`WEATHER_WEEK`. The dead `WEATHER_CLOUDS` mode is left in place, as its comment says.

| Screen | Content |
|---|---|
| Now | Large temperature in the configured unit, the outlook icon, the condition text. A small line carries feels-like, humidity and wind. Updated time at the foot. Honest empty states: no WiFi, not asked yet, service not answering are different sentences. |
| Radar | The existing radar mode, unchanged. |
| 7-Day | Seven rows: day name, icon, high/low, rain chance. Laid out for the 466 px circle: the top and bottom rows are narrower chords, so widths are computed from the row's y, not fixed. |

Units use the existing Weather units setting (Auto / Metric / Imperial). Auto resolves from
the home location, which is metric in Australia. Colours and sizes are named constants, not
literals in render code.

### 4. Icons

New module `src/app/weather/wx_icon.{h,cpp}`:

- `wx_icon::classify(int wmoCode, bool isDay)` returns one of Clear, PartlyCloudy, Cloudy,
  Fog, Drizzle, Rain, Showers, Snow, Thunder (night variants of Clear and PartlyCloudy). Pure
  function, no LVGL, host-testable. It covers every code Open-Meteo documents, and an unknown
  code maps to Cloudy rather than to nothing.
- `wx_icon::create(lv_obj_t *parent, int size)` builds the shapes once as LVGL objects (circles,
  rounded rects, short lines); `wx_icon::set(icon)` shows the right subset and colours. Drawn at
  the size asked, so the same code serves the large Now icon and the small 7-Day icons.
- No baked art, no PSRAM, nothing decoded.

### 5. Data

- `weather_client.cpp`: `forecast_days` 4 -> 7; add `is_day` to `current`. `WeatherSnapshot`
  gains `isDay`, and `days[]` grows to `WEATHER_DAYS 7`. The 4-entry assumptions in `ui.cpp`
  (`i < 4`, the 3-column forecast grid) are replaced.
- Parsing moves out of the fetch into `weather_parse(const char *json, WeatherSnapshot &)` so a
  canned response can test it. The fetch keeps plain HTTP, the User-Agent and the timeouts.
- `WEATHER_REFRESH_MS` stays 30 minutes.
- The native build needs a fetch path. `wx_radar_client.cpp` already uses `native_http.h` under
  `#ifndef ARDUINO`; `weather_fetch` follows the same pattern.

### 6. Theme surface

No new theme keys, so no `THEME_CAPS` bump and no new Studio controls: the new screens read
the existing `weather.bg` and credit styling. `docs/adding-a-screen.md` says a screen is not
finished until Orb Studio agrees with the firmware. The Studio repository is not on this
machine (`~/Developer/hf-sites` does not exist), so Studio parity for Now and 7-Day (text
slots, typefaces, margins, layer order) is recorded as follow-up work, not done here.
`tools/audit.py` is run if it can reach Studio and otherwise its absence is stated.

### 7. Simulator

- The simulator's mock forecast (`sim_main.cpp`) is replaced by the real Open-Meteo fetch at
  the sim's home location. Tested with `ORBLAT=-27.47 ORBLON=153.03` (Brisbane).
- Screenshots of all three screens are captured by driving the knob the way a person does
  (`sim_knob` events), in the pattern of the existing `--wxshot` / `--knobshot`.

## Testing

- Host tests, added to `tests/run_host_tests.sh`: `wx_icon::classify` over every documented
  WMO code, and `weather_parse` against a canned 7-day Brisbane response (day count, units in
  Celsius, missing-field defaults, truncated JSON).
- Simulator: three screenshots at Brisbane; a knob step forward and back wraps; entering the
  app lands on Now; the radar still loads.
- Both `pio run -e native` and `pio run -e esp32-s3-amoled-175` build. `pio` is at
  `~/.platformio/penv/bin/pio`.
- `tests/test_default_theme.py` and the existing host tests pass.
- Not verifiable here, and said so: real display rendering on the AMOLED, memory behaviour of
  the radar buffers alongside the new screens, the knob feel. These are the first hardware
  checks.
